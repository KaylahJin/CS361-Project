# V3-02 Auth & Permission Control Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Implement GitHub issues #99 (login/logout via Cognito), #100 (JWT Authorizer + account matching), and #103 (shared role-based authorization), closing parent epic #97, end to end: Login → Cognito token → API Gateway validates token → Lambda resolves the user → Lambda enforces role/ownership.

**Architecture:** Frontend is a React SPA that talks to Amazon Cognito directly via `amazon-cognito-identity-js` (SRP auth, no Hosted UI, no Amplify) and stores the session in memory + `localStorage` refresh token. API Gateway (HTTP API, already deployed) gets a native JWT authorizer pointed at the Cognito User Pool issuer, attached only to the two existing `coop-plans` routes (the only routes in scope that read personal data). Inside the Lambda, a new `auth.mjs` resolves the verified `sub` claim to a row in `app_users` (identity), and a new `authorize.mjs` enforces the role/ownership rules from `docs/overview/V3-01-workflow-permissions.md` (authorization). Both are plain exported functions called from the existing handlers — no new routing layer, no middleware framework.

**Tech Stack:** React 19 + TypeScript (existing), `amazon-cognito-identity-js` (new, frontend-only), Vitest + `@testing-library/react` (new, frontend tests — no test coverage exists under `src/` today), Terraform (existing, `aws_cognito_user_pool` + `aws_apigatewayv2_authorizer`, both new resource types in this repo), Node.js `nodejs22.x` Lambda in plain `.mjs` (existing pattern in `infra/lambda/companies/`), `pg` (existing, no new backend npm deps).

**Spec:**
- `docs/overview/V3-01-data-model.md` — `app_users`, `advisor_student_assignments` table shapes
- `docs/overview/V3-01-api-spec.md` — error codes, "trust only the verified `sub`" rule
- `docs/overview/V3-01-workflow-permissions.md` — the role × permission rules this plan encodes
- GitHub issues #97 (epic), #99, #100, #103 — acceptance criteria quoted inline per task below

## Global Constraints

- Lambda code is plain ESM `.mjs` on `nodejs22.x`, colocated in `infra/lambda/companies/`, matching every existing handler in that directory. No new backend npm dependency — `pg` already covers everything needed.
- Frontend: no router library, no component library, no CSS-in-JS, no `clsx`/`cva`. Styling is inline Tailwind utility classes per `CLAUDE.md` §6. New components use the dual `export const X / export default X` pattern.
- Tailwind v4 CSS-first config stays as-is — do not add `tailwind.config.js` or `postcss.config.js`.
- `"noUnusedLocals"`, `"noUnusedParameters"`, `"verbatimModuleSyntax": true` are on — unused imports are build failures, type-only imports need `import type`.
- All SQL is parameterized (`$1`, `$2`, …) through the `pg` driver's values array — never string-interpolated, matching the existing convention in `listCoopPlans.mjs` / `getCoopPlanById.mjs`.
- CORS is set **only** in `infra/terraform/apigateway.tf`'s native API Gateway config. `response.mjs`'s `jsonResponse` must never gain an `Access-Control-*` header.
- Identity comes **only** from the verified JWT `sub` claim at `event.requestContext.authorizer.jwt.claims.sub`. No handler may read a caller-supplied `studentId`/`userId` and treat it as "who is calling" — only as a filter/target to be checked against the verified identity.
- **External blocker:** `app_users` and `advisor_student_assignments` don't exist in the deployed DB yet — they ship in issue #98 (V3-03.1, assigned to a teammate, still OPEN). Tasks 3 and 4 are fully codable and unit-testable now (DB access is mocked in tests, same as every existing `*.test.mjs` in this directory), but the live integration check (Task 3 Step 6, Task 4 Step 6) cannot run against a real deployed DB until #98 merges. Each of those steps says so explicitly — do not treat a skipped live check as a failed task.
- **Credentials:** this session's AWS Academy Lab token is expired (`aws sts get-caller-identity` → `ExpiredToken`). Every `terraform apply` step in this plan is marked **MANUAL** — it needs a human to refresh Lab credentials and run it; an agent executing this plan runs `terraform validate`/`plan` only and stops there.

## Review Focus

1. An expired/forged Cognito token against a route behind the new JWT authorizer must get **401 straight from API Gateway**, never reach the Lambda and come back as a 500. Task 3 Step 6 adds a manual `curl` check for this because API Gateway's own rejection can't be unit-tested from inside the Lambda test suite.
2. A Student passing someone else's id in a query/path param (e.g. `GET /coop-plans?studentId=OTHER`) must not widen their own result set — the ownership filter must **AND** with the role filter, never be bypassable by a request parameter. Covered in Task 4 Step 2's test for `listCoopPlans`.
3. An `app_users` row that exists but has `is_active = false` must come back as **401** (treated as not authenticated), not 403 — `getAuthenticatedUser` returns `null` for inactive rows so the caller is indistinguishable from "no account at all." Covered in Task 3 Step 1.
4. An `ADMIN`-only account (no separate `STAFF`/`ADVISOR` row) hitting either coop-plan route must get **403**, never fall through a default-allow branch. Covered in Task 4 Step 1's `authorize.test.mjs`.
5. An Advisor who *was* assigned to a student but had the assignment removed must be **re-checked per request** against `advisor_student_assignments` — never cached in the token, session, or a module-level map. `authorize.mjs` queries fresh every call; its doc comment says so explicitly to stop a future "optimization" from adding a cache. Covered in Task 4 Step 1.

```hcl
    require_lowercase = true
    require_uppercase = true
    require_numbers   = true
    require_symbols   = false

      name     = "verified_email"
      priority = 1

  refresh_token_validity = 30   # days
```

```ts
// src/auth/cognitoClient.ts
import {
  CognitoUser,
  CognitoUserPool,
  AuthenticationDetails,
} from 'amazon-cognito-identity-js';
import { cognitoConfig } from './cognitoConfig';

export interface Session {
  idToken: string;
  email: string;
}

const pool = new CognitoUserPool({
  UserPoolId: cognitoConfig.userPoolId,
  ClientId: cognitoConfig.clientId,
});

export function login(email: string, password: string): Promise<Session> {
  const user = new CognitoUser({ Username: email, Pool: pool });
  const details = new AuthenticationDetails({
    Username: email,
    Password: password,
  });

  return new Promise((resolve, reject) => {
    user.authenticateUser(details, {
      onSuccess: (result) => {
        resolve({ idToken: result.getIdToken().getJwtToken(), email });
      },
      onFailure: (err) => reject(err),
    });
  });
}

export function logout(): void {
  const current = pool.getCurrentUser();
  current?.signOut();
}

export function getCurrentSession(): Promise<Session | null> {
  const current = pool.getCurrentUser();
  if (!current) return Promise.resolve(null);

  return new Promise((resolve) => {
    current.getSession((err: Error | null, session: { getIdToken: () => { getJwtToken: () => string } } | null) => {
      if (err || !session) {
        resolve(null);
        return;
      }
      resolve({ idToken: session.getIdToken().getJwtToken(), email: current.getUsername() });
    });
  });
}
```

```tsx
import React, { createContext, useCallback, useContext, useEffect, useState } from 'react';
import * as cognitoClient from './cognitoClient';

type Status = 'loading' | 'authenticated' | 'anonymous';

interface AuthState {
  status: Status;
  user: { email: string } | null;
  idToken: string | null;
  login: (email: string, password: string) => Promise<void>;
  logout: () => void;
}

const AuthContext = createContext<AuthState | null>(null);

export const AuthProvider: React.FC<{ children: React.ReactNode }> = ({ children }) => {
  const [status, setStatus] = useState<Status>('loading');
  const [user, setUser] = useState<{ email: string } | null>(null);
  const [idToken, setIdToken] = useState<string | null>(null);

  useEffect(() => {
    let cancelled = false;
    cognitoClient.getCurrentSession().then((session) => {
      if (cancelled) return;
      if (session) {
        setUser({ email: session.email });
        setIdToken(session.idToken);
        setStatus('authenticated');
      } else {
        setStatus('anonymous');
      }
    });
    return () => {
      cancelled = true;
    };
  }, []);

  const login = useCallback(async (email: string, password: string) => {
    const session = await cognitoClient.login(email, password);
    setUser({ email: session.email });
    setIdToken(session.idToken);
    setStatus('authenticated');
  }, []);

  const logout = useCallback(() => {
    cognitoClient.logout();
    setUser(null);
    setIdToken(null);
    setStatus('anonymous');
  }, []);

  return (
    <AuthContext.Provider value={{ status, user, idToken, login, logout }}>
      {children}
    </AuthContext.Provider>
  );
};
export default AuthProvider;

export function useAuth(): AuthState {
  const ctx = useContext(AuthContext);
  if (!ctx) throw new Error('useAuth must be used within AuthProvider');
  return ctx;
}
```

```js
// ============================================================
// CS361 V3-02.2 — resolve the verified Cognito sub to an app_users row
// ============================================================
// API Gateway's JWT authorizer (see infra/terraform/cognito.tf) has
// already verified the token's signature and expiry before this Lambda
// ever runs — this module only maps the already-verified `sub` claim to
// our own notion of a user. It never re-validates the token itself.
//
// Returns null for every "not a usable identity" case (no claim, no row,
// inactive row) on purpose: all of those must produce 401 to the caller,
// and collapsing them to one return value is what makes that automatic
// at the call site instead of relying on three separate checks.
// ============================================================

import { getPool } from './db.mjs';

/**
 * @param {{requestContext?: {authorizer?: {jwt?: {claims?: Record<string, string>}}}}} event
 * @returns {Promise<{sub: string, role: string, studentId: string | null} | null>}
 */
export async function getAuthenticatedUser(event) {
  const sub = event?.requestContext?.authorizer?.jwt?.claims?.sub;
  if (!sub) return null;

  const result = await getPool().query(
    'SELECT cognito_sub, role, student_id, is_active FROM app_users WHERE cognito_sub = $1',
    [sub],
  );

  const row = result.rows[0];
  if (!row || !row.is_active) return null;

  return { sub: row.cognito_sub, role: row.role, studentId: row.student_id };
}
```

```js
// ============================================================
// CS361 V3-02.3 — shared role/ownership authorization for coop-plans
// ============================================================
// Every check here re-queries advisor_student_assignments fresh on every
// call — no module-level cache, no cache in the JWT or session. An
// assignment can be revoked between two requests from the same advisor;
// caching this would let a revoked advisor keep seeing a student's plan
// until the cache expired. Do not add caching here.
// ============================================================

import { getPool } from './db.mjs';

export class ForbiddenError extends Error {}

/**
 * @param {{sub: string, role: string, studentId: string | null}} user
 * @returns {Promise<{sql: string, params: unknown[]}>}
 */
export async function buildCoopPlanListFilter(user) {
  if (user.role === 'STUDENT') {
    return { sql: 'p.student_id = $PARAM', params: [user.studentId] };
  }
  if (user.role === 'ADVISOR') {
    return {
      sql: 'p.student_id IN (SELECT student_id FROM advisor_student_assignments WHERE advisor_sub = $PARAM)',
      params: [user.sub],
    };
  }
  if (user.role === 'STAFF') {
    return { sql: '', params: [] };
  }
  throw new ForbiddenError(`role ${user.role} has no coop-plan list access`);
}

/**
 * @param {{sub: string, role: string, studentId: string | null}} user
 * @param {{student_id: string}} plan
 * @returns {Promise<void>}
 */
export async function assertCanViewPlan(user, plan) {
  if (user.role === 'STAFF') return;

  if (user.role === 'STUDENT') {
    if (user.studentId === plan.student_id) return;
    throw new ForbiddenError('student does not own this plan');
  }

  if (user.role === 'ADVISOR') {
    const result = await getPool().query(
      'SELECT student_id FROM advisor_student_assignments WHERE advisor_sub = $1 AND student_id = $2',
      [user.sub, plan.student_id],
    );
    if (result.rows.length > 0) return;
    throw new ForbiddenError('advisor is not assigned to this student');
  }

  throw new ForbiddenError(`role ${user.role} has no coop-plan view access`);
}
```

```js
      throw err;
    }

    return jsonResponse(200, plan);
  } catch (err) {
    console.error('getCoopPlanById failed', err);
    return jsonResponse(500, { error: 'Internal server error' });
  }
}
```
