หน่วยที่ใช้:

- E2E: มิลลิวินาที
- API response: เวลาที่เบราว์เซอร์สังเกตได้ หน่วยมิลลิวินาที
- จำนวน Request: จำนวน request ไปยัง `/companies` ต่อการทดสอบหนึ่งรอบ
- Response bytes: จำนวนไบต์ของ response body
- Response rows: จำนวนแถวที่อ่านได้จาก JSON array/object

ชุดทดสอบหลังปรับปรุงมี 120 รอบที่สำเร็จ ได้แก่ S1, S2, S3 และ S4 อย่างละ 30 รอบ ทั้ง 120 รอบได้ HTTP 200 และจำนวนแถวตรงตามที่คาดหวัง

ผล benchmark หลังปรับปรุงที่เก็บภายหลังนี้ไม่ได้นำมาอ้างว่า latency ดีขึ้นในทุกกรณี เนื่องจากช่วงเวลาทดสอบ สภาพเครือข่าย สภาพแวดล้อม Lambda และ session ของ AWS แตกต่างกัน ดังนั้น latency ของ S1/S3 อาจแย่ลง แม้จำนวน request จะลดลงตามโครงสร้างก็ตาม

## 4. ค่าใช้จ่ายโดยประมาณ

การประมาณค่าใช้จ่ายใช้อัตราสาธารณะของ AWS Region US East (N. Virginia) ที่ตรวจสอบเมื่อวันที่ 2026-11-26

แหล่งอ้างอิง:

- [ราคา AWS Lambda](https://aws.amazon.com/lambda/pricing/)
- [ราคา Amazon API Gateway](https://aws.amazon.com/api-gateway/pricing/)
- [ราคา Amazon RDS for PostgreSQL](https://aws.amazon.com/rds/postgresql/pricing/)

### สมมติฐาน

- API Gateway: HTTP API ราคา $1.00 ต่อหนึ่งล้าน requests
- Lambda: $0.20 ต่อหนึ่งล้าน requests
- Lambda: หน่วยความจำ 128 MB สถาปัตยกรรม x86 ราคา $0.0000020833375 ต่อวินาทีที่ทำงาน ใน tier แรกที่ประกาศราคา
- การถ่ายโอนข้อมูล: สมมติราคา $0.09 ต่อ GB สำหรับการส่งข้อมูลออกสู่อินเทอร์เน็ต ใช้เพื่อการวางแผนเท่านั้น
- RDS: `db.t4g.micro`, พื้นที่จัดเก็บ gp3 ขนาด 20 GB, เปิดให้เข้าถึงจากภายนอก และกำหนดค่าแบบ Single-AZ
- ไม่รวมผลของ Free Tier และเครดิตส่วนลดที่ตกลงเป็นกรณีพิเศษ
- ไม่ถือว่าเวลา Lambda หรือเวลาที่ RDS ทำงาน/ว่าง ถูกใช้โดย benchmark นี้เพียงอย่างเดียว
- ข้อมูลจาก AWS Cost Explorer ยังเป็นค่าใช้จ่ายประมาณการจนกว่ารอบบิลจะปิด

### การเปิดหน้า S1 จำนวน 100,000 ครั้ง

| รายการ | ก่อนปรับปรุง | หลังปรับปรุง | ความแตกต่าง |
|---|---:|---:|---:|
| จำนวน requests ไปยัง `/companies` | 200,000 | 100,000 | ลดลง 100,000 |
| ขนาด API payload | 11.032 GB | 5.516 GB | ลดลง 5.516 GB |
| ค่า API Gateway | $0.2000 | $0.1000 | ลดลง $0.1000 |
| ค่า Lambda ตามจำนวน requests | $0.0400 | $0.0200 | ลดลง $0.0200 |

ค่าประมาณจำนวน requests ของ API และ Lambda ยังไม่รวมค่าเวลาในการทำงาน การ retry, cold start, throttling, ภาษี, เครดิตส่วนลด และค่า RDS คงที่

ตัวอย่างเพิ่มเติมโดยสมมติว่า Lambda ทำงาน 200 ms ต่อ invocation:

- 128 MB = 0.125 GB
- 200 ms = 0.2 วินาที
- 0.125 GB × 0.2 วินาที × $0.0000166667/GB-second = $0.000000416667 ต่อ invocation
- ก่อนปรับปรุง 200,000 invocations: ประมาณ $0.08333
- หลังปรับปรุง 100,000 invocations: ประมาณ $0.04167
- ค่า Lambda ด้านระยะเวลาที่ประหยัดได้โดยประมาณ: $0.04167

ตัวอย่างระยะเวลานี้เป็นสมมติฐานเพื่อการวางแผน ไม่ใช่ข้อมูลค่าใช้จ่าย Lambda ที่วัดจาก billing จริง

## 5. ค่าใช้จ่าย RDS และค่าใช้จ่ายคงที่

RDS คิดค่าบริการตามชั่วโมงที่ DB instance ทำงานและพื้นที่จัดเก็บ ไม่ได้คิดโดยตรงจากจำนวนแถวของ `/companies` หรือ query latency

ไม่มีหลักฐานจาก benchmark นี้ที่ยืนยันว่า query ที่เร็วขึ้นทำให้ค่า RDS ลดลง DB instance ยังคงเป็น `db.t4g.micro` และใช้ gp3 ขนาด 20 GB โดยไม่มีการบันทึกการหยุด/เริ่ม instance หรือการเปลี่ยนแปลงการคิดค่าบริการ ดังนั้นให้ถือค่า RDS เป็นค่าใช้จ่ายคงที่ในช่วง benchmark นี้ เว้นแต่จะมีหลักฐานจาก billing หรือ configuration แสดงเป็นอย่างอื่น

ช่วงข้อมูลจริง/ประมาณการจาก Cost Explorer:

- ช่วงบิล: 2026-11-01 ถึง 2026-11-25
- Amazon API Gateway: USD 0.000721
- AWS Lambda: USD 0
- Amazon RDS: USD 5.5692656918
- AmazonCloudWatch: USD 0.0189633316
- ค่าทั้งหมดเป็นประมาณการค่าใช้จ่ายระดับบัญชี และผลลัพธ์จาก AWS ระบุว่าช่วงเวลานี้ยังเป็นข้อมูลประมาณการ

หลักฐาน billing นี้แสดงยอดรวมตามบริการในระดับบัญชี โดยไม่รวม identifier ที่มีความอ่อนไหวของบัญชี

## 6. ข้อผิดพลาด, Throttling และข้อจำกัด

- ทุกสถานการณ์ในชุด benchmark หลังปรับปรุงได้ HTTP 200 และจำนวนแถวตรงตามที่คาดหวัง
- ไม่พบ HTTP error หรือ throttle ในผลการทดสอบหลังปรับปรุงชุดสุดท้าย
- E2E latency ที่วัดจากเบราว์เซอร์รวมเวลาเครือข่าย การแสดงผลของเบราว์เซอร์ และเวลาฝั่ง backend
- ระยะเวลาของ API response เป็นค่าที่เบราว์เซอร์สังเกตได้ ไม่ใช่ระยะเวลาทำงานของ Lambda
- การทดสอบก่อนและหลังทำคนละช่วงเวลาและคนละ network session
- ไม่มีการจำแนก cold start สำหรับ benchmark หลังปรับปรุงชุดสุดท้าย
- ยังไม่มีใบแจ้งค่าใช้จ่าย AWS รายเดือนฉบับสรุปสำหรับช่วงทดสอบ
- ไม่สามารถระบุว่าค่า RDS ลดลงเพราะ query เร็วขึ้นได้ หากไม่มีหลักฐาน billing และชั่วโมงการทำงานของ instance
