1. Role-Based Access Control Matrix for Review Operations
---------------------------------------------------------
| Role         | GET /coop-plans (List)       | GET /coop-plans/{id} (View)   | POST /coop-plans/{id}/review (Review) |
|--------------|------------------------------|-------------------------------|---------------------------------------|
| Anonymous    | 401 Unauthorized             | 401 Unauthorized              | 401 Unauthorized                      |
| STUDENT      | 200 (Own plans only)         | 200 (Own plan) / 403 (Other)  | 403 Forbidden                         |
| ADVISOR      | 200 (Assigned students only) | 200 (Assigned) / 403 (Other)  | 200 (Assigned) / 403 (Other)          |
| STAFF        | 200 (All programme plans)    | 200 (All programme plans)     | 200 (All programme plans)             |
| ADMIN        | 403 Forbidden                | 403 Forbidden                 | 403 Forbidden                         |

2. Key Security Properties Verified
-----------------------------------
1) Role Enforced Server-Side:
   Client JWT token claims are decoded by API Gateway Authorizer and verified against
   `app_users` table in RDS PostgreSQL (`assertCanReviewPlan`).
2) Zero-Trust Student ID:
   Reviewers cannot inspect or review plans outside their advisor assignment.
   Query parameters never widen scope.
3) Admin Restriction:
   Per V3-01 architecture, ADMIN alone has no permission to review or view plans
   (answers 403 Forbidden). Must have ADVISOR or STAFF role to inspect/review.
4) No Mock Fallback:
   When 401 or 403 is returned, the frontend does not fall back to local mock data.
   Unauthenticated and Forbidden states are rendered with clear guidance.
