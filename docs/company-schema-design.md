| 3 | `province` | `TEXT` | **Yes — NOT NULL** | — | — | **Yes** | province dropdown; exact match in filter |

| 8 | `url` | `TEXT` | No | Yes | — | — | card link target |

## 2. Search and Filter — which fields, and how

From `infra/lambda/companies/listCompanies.mjs`. Both query params are optional and combine with `AND`.

| Param | SQL | Fields | Match type | Index used |
|---|---|---|---|---|
| `?search=` | `(name ILIKE $1 OR short_name ILIKE $1)` | `name`, `short_name` | partial, case-insensitive, `%term%` | `idx_companies_name`, `idx_companies_short_name` (GIN trigram) |
| `?province=` | `province = $2` | `province` | exact | `idx_companies_province` (btree) |

`search` covers `short_name` as well as `name` so that typing `KBTG` or `SCB` finds a company whose legal name is Thai-only.

An empty or whitespace-only value counts as not provided, so `?search=` does not become `ILIKE '%%'`.

Nothing else is searchable or filterable in V2 scope.

### Indexes that exist for this

```
companies_pkey             UNIQUE btree (company_id)      -- get by id
idx_companies_province     btree (province)               -- filter, #28
idx_companies_name         gin (name gin_trgm_ops)        -- search, #27
idx_companies_short_name   gin (short_name gin_trgm_ops)  -- search, #27
```

## 3. Schema covers what the Employers page needs

Every field the V1 Employers page rendered has a column. Mapping against `src/pages/Employers.tsx`:

| Page element | Column | Behaviour when missing |
|---|---|---|
| Logo image | `logo_filename` | `onError` swaps in a box showing `short_name \|\| company_id` |
| Card title | `name` | NOT NULL, cannot be missing |
| Card subtitle | `location` | NOT NULL, cannot be missing |
| Card link | `url` | optional; renders without a destination |
| Province dropdown | `province` | NOT NULL; options and counts are derived from the data, not hardcoded |
| Partner count in hero | — | `data.length`, live from the API |

The dropdown and the hero count are both computed from the API response, so neither needs a schema change when companies are added.

`description` is empty for all 103 rows — intentional, it is a V3 field.

## 6. Fields beyond the V2.md ERD

V2.md's diagram lists `company_id, name, province, location, description`. `short_name`,
`logo_filename` and `url` were added because the V1 Employers page already displays them —
dropping them would break that page. V2.md states that exact physical fields are finalized
here, not in the diagram.

## 7. Known gaps

- `C19` (บริษัท โปรทอส เทคโนโลยี จำกัด) and `C88` (บริษัท ร่วมเจริญพัฒนา จำกัด (มหาชน)) appear in the
  official 2568 registry but were never on the V1 Employers page. V1 is the source of truth,
  so they are not seeded; `build-seed.mjs` reports them on every run. Seeding them would make
  the count 105.
- 6 of the 103 referenced logo files exist in `public/images/logos/`. The other 97 cards fall
  back to the `short_name` box by design.
- `CompanyListResponse` in `src/types/company.ts` describes a `{ companies, total }` shape the
  API does not return — it returns a bare array. Unused type, no runtime effect.
